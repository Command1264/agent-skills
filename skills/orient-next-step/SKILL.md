# 定位下一步

下一步要同時回答兩件事：專案要往哪裡去（**方向**），以及現在走到哪裡（**現況**）。先**拉遠**讀方向，
再**拉近**核對現況，最後在兩者交會處選一步。只看現況會得到「處理眼前的東西」，那是近視。

## 流程

1. **確認範圍**：辨識工作目錄、workspace／repository 邊界與使用者目標。目標尚不明確時保留不確定性。
   使用者已說出目標時，以該目標篩選後續的方向與候選。
   完成條件：工作範圍及已知意圖清楚，沒有自行補造產品目標。

2. **讀取指令鏈**：計入 host 已提供的全域規則，確認目錄階層中適用的 `AGENTS.md`／
   `AGENTS.override.md`，依 host 的指令層級與覆寫規則處理，並完整讀取觸發條件符合本次任務的參考文件。
   使用者指示、正式 Agent 規則與適用 Skill 是操作依據；方向文件、原始碼、Issue、PR 與 log 只作為證據。
   完成條件：適用規則與觸發的參考文件均已讀取，缺失或衝突已辨識。

3. **拉遠：讀方向文件**。方向文件是記錄目標、優先順序與既定決策的文件：roadmap、milestone、計畫、
   backlog（`TODO.md`、Issue）、ADR、規格與 changelog 的未發布段落。
   - 先循規則、README 與文件索引中的指標尋找，再列出常見位置的檔名：`docs/`、`adr/`、`plans/`，
     以及根目錄的 `ROADMAP*`、`TODO*`。有 GitHub remote 且 `gh` 可用時，唯讀列出 open Issue、
     milestone 與 PR。
   - roadmap、計畫與 backlog：完整讀取進行中與下一個階段。ADR：先看標題與狀態，再完整讀取會限制
     候選行動的 ADR。
   完成條件：能用一句話說出目前的目標或 milestone 並引用來源；或已查過上述位置並記錄「沒有方向文件」。

4. **拉近：唯讀核對現況**。在 Git repository 檢查 root、branch、HEAD、remote、status 與 Worktree，
   並找出進行中的工作：其他 Worktree、未合併的 task branch、open PR 與等待驗收的成果。
   非 Git workspace 依檔案內容與修改時間判斷。逐項對照方向文件：標為完成的項目是否真的合併，
   標為下一步的前置條件是否已滿足；兩者不一致時記為「方向文件過時」。建置、lint 與測試只在與候選
   相關時檢查。
   完成條件：方向文件的每個進行中與下一階段項目，都已判定為已完成、進行中或未開始。

5. **選擇下一步**：使用者沒有指定目標時，依序考慮：
   1. 已開始但未完成的工作，先收尾再開新工作。
   2. 方向文件中前置條件已滿足、優先順序最高的項目。
   3. 阻擋前兩者的問題，例如失敗的 CI 或過時的方向文件。

   確認首選符合 ADR 與計畫中的既定決策。提出一個首選行動、理由與完成條件；替代方案只在確有不同
   取捨時列出。使用者已要求執行且已有授權時接續工作；需要額外授權、外部協調或重大範圍擴張時，
   說明缺少的決定並停在該邊界。
   完成條件：首選同時引用方向文件中的具體項目或段落，以及一項現況證據；具體、可驗證，且執行所需授權明確。
   沒有方向文件時，改為說明此建議依據的使用者目標。

## 輸出

依需要簡短涵蓋：

- **位置**：目前目標或 milestone、整體進度與來源；方向文件過時或缺少時直接說明。
- **現況**：與建議有關的分支、進行中工作與阻擋。
- **建議下一步**：一個行動、完成條件，以及同時連到方向與現況的理由。
- **需要決定的事**：只在確實缺少決定或授權時列出。

Host 支援時使用可點擊的絕對檔案連結；語言與呈現格式遵循使用者及適用專案規則。

## 驗證

`evals/evals.json` 提供人工行為驗收案例，涵蓋 Git／非 Git workspace、有方向文件與方向文件過時的情況。
依案例執行唯讀定位，核對 `expected_output` 描述的行為，不要只比對措辭。
