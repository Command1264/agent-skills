# 以個別 Compute Routes 請求建立通勤樣本

第一版針對每個日期、方向、交通模式與公司各送出一次 Compute Routes 請求，只採用主要建議路線，不要求替代路線，也不導入 Compute Route Matrix。早上查詢住家到公司，晚上查詢公司到住家；暫時性網路錯誤、HTTP `429` 與 `5xx` 最多重試兩次並遵守 `Retry-After`，其他 `4xx` 不重試。程式在請求前以 `60 QPM` 為預設值、一次一筆主動節流，允許設定 `1–3000 QPM`；此值只限制本機程序，不宣稱反映 Google Cloud project 的實際剩餘 quota，`429` 只作為異常復原。這讓每筆樣本、成本與錯誤歸屬保持清楚，代價是批次公司數量增加時 HTTP 請求數會線性成長；Request Preview、成本確認門檻與完整必要樣本規則負責限制風險。
