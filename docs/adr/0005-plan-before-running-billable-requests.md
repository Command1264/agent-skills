# 在執行付費請求前產生不可變計畫

`commute-analyzer` 採兩階段 interface：`plan` 完成所有本機驗證、日期展開、請求計數與預覽但不呼叫 API，並以完整有效內容產生 `plan_id`；`run` 只執行既有計畫。正常請求數不超過預設二十筆時，Agent 顯示預覽後可接續執行；超過門檻時，必須取得使用者對同一 `plan_id` 的明確確認，任何設定變動都使原計畫失效。跨 Skill JSON envelope 嚴格拒絕未知欄位，`stdout` 只輸出 JSON、`stderr` 承載診斷，並以 exit code `0`、`2`、`3`、`4` 分別表示完整成功、輸入或設定錯誤、部分成功與外部服務失敗。這讓成本與實際執行內容可稽核，代價是每次分析至少需要 plan 與 run 兩個步驟。
